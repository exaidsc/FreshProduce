## 一、订单多表关联设计（正文）

订单采用 **订单主表 `order` + 订单明细表 `order_item`** 的经典双表联动结构，核心设计要点如下：

1. **一对多关系**：一个订单对应多条明细。`order_item.order_id` 外键关联 `order.id`，并配置 `ON DELETE CASCADE`，删除主表订单时明细自动级联删除，避免脏数据。
2. **商品快照**：明细表冗余存储 `product_name`、`product_image`、`price`，下单瞬间把商品当时的名称、图片、成交价定格下来。即使后续商家修改商品或下架，历史订单依然可正确展示，保证数据可追溯。
3. **总价由明细聚合**：`order.total_amount` 在创建事务内由 `Σ(price × quantity)` 计算得到，明细为权威来源。
4. **团购关联**：`order.activity_id` 关联 `group_activity`，可为空（普通订单）；支付后写入 `group_join` 参团记录并 `current_people + 1`。
5. **状态字典**：`status` 取值 `0待付款 / 1待成团 / 2待配送 / 3配送中 / 4已完成 / 5已取消`，由后端白名单强制管控（见第三章）。

ER 简化关系：

```
user 1───* order 1───* order_item *───1 product
                  │
                  └──* group_join *───1 group_activity
```

## 二、数据库事务应用场景分析（正文）

“下单减库存 + 生成订单”是典型的 **强一致性** 场景，必须放在数据库事务（`BEGIN / COMMIT / ROLLBACK`）中，否则会出现：

- 库存扣了但订单没生成（用户钱扣了没单）；
- 订单生成了但库存没扣（超卖，多人买到同一件商品）；
- 明细插入失败导致订单与明细数量不一致。

本项目在 `createOrder` 中开启事务，并按顺序执行：校验地址 → 对商品行 `SELECT ... FOR UPDATE` 加悲观锁 → 校验并扣减库存/累加销量 → 插入主表 → 批量插入明细 → 清空购物车 → `COMMIT`；任意一步抛错则整段 `ROLLBACK`，库存与订单回到下单前状态。

**悲观锁（行锁）** 用于并发下单：`FOR UPDATE` 让同一商品在事务提交前被串行处理，从根本上杜绝超卖。配合 MySQL InnoDB 的 RR 隔离级别，是“高并发下单数据一致性”的基石（详见第三章）。

## 三、高并发下单数据一致性解决方案（正文）

1. **库存预扣（下单即减）**：用户提交订单即扣库存（`stock - qty`），状态停留在 `0 待付款`。这样库存永远 ≥ 0，避免“支付时才减库存”导致的超卖。
2. **超时回补**：若 30 分钟内未支付，定时任务 `autoCancelExpiredOrders` 自动把订单置为 `5 已取消` 并把库存、销量加回（`stock + qty, sales - qty`），防止库存被长期“假占用”。
3. **行级悲观锁**：`SELECT ... FOR UPDATE` 串行化同一商品的并发写，保证扣减原子性。
4. **取消回补的闭环**：用户/管理员取消（0、1、2 态）时同样回补库存；若已支付团购订单取消，还额外删除 `group_join` 并 `current_people - 1`，保证团购人数准确。
5. **状态机兜底**：所有状态变更走白名单 `STATUS_FLOW`，非法流转（如“配送中→待付款”）直接拒绝，前端无法越权。

## 四、数据统计算法设计（正文）

统计口径统一为 **有效订单**（`status IN (1,2,3,4)`，即已支付及之后状态），排除“待付款”与“已取消”。四个统计模块算法：

- **销量统计**：`SUM(order_item.quantity)` 得总件数，`SUM(quantity × price)` 得总销售额，并按日分组形成趋势。
- **订单统计**：按 `status` 分组得到状态分布（漏斗），按日分组得到下单趋势。
- **营收统计**：对有效订单按 `DATE(create_time)` 分组 `SUM(total_amount)`，得每日营收。
- **热门商品统计**：以 `product_id` 聚合销量与销售额，`ORDER BY sold_count DESC` 取 TOP N，并标注排名 `rank`。

**图表数据封装逻辑**：后端只返回“已聚合、可直接渲染”的结构化 JSON（如 `by_day: [{day, sales}]`、`hot_products: [{rank, product_name, sold_count}]`），前端（Vue ECharts / 小程序）无需再做二次聚合，直接喂给图表组件即可。日期区间通过 `start` / `end` 参数过滤，由 `buildDateCondition` 以参数化查询（占位符）拼接，杜绝 SQL 注入。

## 五、后端异常处理、容错机制设计（正文）

1. **统一响应**：`utils/response.js` 的 `success/fail/serverError` 保证所有接口返回 `{ code, message, data }`，前端按 `code` 分支处理。
2. **事务回滚容错**：下单、支付、取消均 `try { ... } finally { conn.release() }` 包裹，出错必回滚、连接必释放，避免连接泄漏。
3. **参数与业务校验**：购物车/下单对 `product_id`、`quantity`、商品上下架、库存充足性做前置校验；上传接口用 multer `fileFilter` 限制图片类型与 5MB 大小。
4. **异常订单定时清理**：`scheduler/orderScheduler.js` 每 5 分钟扫描超时未支付订单并自动取消回补，属于“自愈”容错。
5. **全局错误中间件**：`app.js` 末尾统一捕获未处理异常，返回 `code:500` 而不直接崩溃进程。
6. **上传目录幂等**：`uploadController` 启动时 `fs.mkdirSync(UPLOAD_DIR, { recursive:true })`，文件名带时间戳+随机串，避免覆盖与中文乱码。

```javascript
async function createOrder(userId, payload) {
    const { address_id, items, activity_id, remark, cart_ids } = payload;
    if (!address_id) throw new Error('收货地址不能为空');
    if (!items || !Array.isArray(items) || items.length === 0) throw new Error('订单商品不能为空');

    const conn = await pool.getConnection();
    try {
        await conn.beginTransaction();

        // 1. 收货地址归属校验
        const [addr] = await conn.query(
            'SELECT id FROM address WHERE id = ? AND user_id = ?', [address_id, userId]);
        if (addr.length === 0) throw new Error('收货地址不存在');

        // 2. 团购活动有效性（加锁）
        let activity = null;
        if (activity_id) {
            const [acts] = await conn.query(
                'SELECT * FROM group_activity WHERE id = ? FOR UPDATE', [activity_id]);
            if (acts.length === 0) throw new Error('团购活动不存在');
            activity = acts[0];
            if (activity.status !== 1) throw new Error('团购活动已结束');
        }

        // 3. 逐商品加行锁、校验库存、快照、扣库存
        const orderItems = [];
        let totalAmount = 0;
        for (const it of items) {
            const pid = it.product_id, qty = parseInt(it.quantity);
            if (!pid || !qty || qty < 1) throw new Error('商品参数不合法');

            const [prods] = await conn.query(
                'SELECT * FROM product WHERE id = ? FOR UPDATE', [pid]);
            if (prods.length === 0) throw new Error(`商品不存在: ${pid}`);
            const p = prods[0];
            if (p.status !== 1) throw new Error(`商品已下架: ${p.name}`);
            if (p.stock < qty) throw new Error(`库存不足: ${p.name}`);

            let unitPrice = p.price;
            if (activity && activity.product_id === pid) unitPrice = activity.group_price;

            await conn.query('UPDATE product SET stock = stock - ? WHERE id = ?', [qty, pid]);
            await conn.query('UPDATE product SET sales = sales + ? WHERE id = ?', [qty, pid]);

            orderItems.push({ product_id: pid, product_name: p.name,
                product_image: p.image, price: unitPrice, quantity: qty });
            totalAmount += unitPrice * qty;
        }

        // 4. 插入主表（初始 待付款，库存已扣）
        const orderNo = genOrderNo();
        const [orderRes] = await conn.query(
            `INSERT INTO \`order\` (order_no,user_id,address_id,activity_id,total_amount,status,remark)
             VALUES (?,?,?,?,?,?,?)`,
            [orderNo, userId, address_id, activity_id || null,
             Number(totalAmount.toFixed(2)), ORDER_STATUS.PENDING_PAY, remark || '']);
        const orderId = orderRes.insertId;

        // 5. 批量插入明细
        for (const oi of orderItems) {
            await conn.query(
                `INSERT INTO order_item (order_id,product_id,product_name,product_image,price,quantity)
                 VALUES (?,?,?,?,?,?)`,
                [orderId, oi.product_id, oi.product_name, oi.product_image, oi.price, oi.quantity]);
        }

        // 6. 清空已下单购物车
        if (Array.isArray(cart_ids) && cart_ids.length > 0) {
            await conn.query('DELETE FROM cart WHERE user_id = ? AND id IN (?)', [userId, cart_ids]);
        }

        await conn.commit();
        return { order_id: orderId, order_no: orderNo,
                 total_amount: Number(totalAmount.toFixed(2)), status: ORDER_STATUS.PENDING_PAY };
    } catch (err) {
        await conn.rollback();
        throw err;
    } finally {
        conn.release();
    }
}
```

```javascript
async function cancelOrder(orderId, userId, isAdmin = false) {
    const conn = await pool.getConnection();
    try {
        await conn.beginTransaction();
        const [orders] = await conn.query(
            'SELECT * FROM `order` WHERE id = ?' + (isAdmin ? '' : ' AND user_id = ?') + ' FOR UPDATE',
            isAdmin ? [orderId] : [orderId, userId]);
        if (orders.length === 0) throw new Error('订单不存在');
        const order = orders[0];
        if (!canTransition(order.status, ORDER_STATUS.CANCELLED))
            throw new Error(`订单状态为「${STATUS_TEXT[order.status]}」，无法取消`);

        const [items] = await conn.query(
            'SELECT product_id, quantity FROM order_item WHERE order_id = ?', [orderId]);
        for (const it of items) {
            await conn.query(
                'UPDATE product SET stock = stock + ?, sales = sales - ? WHERE id = ?',
                [it.quantity, it.quantity, it.product_id]);
        }
        if (order.status === ORDER_STATUS.PENDING_GROUP && order.activity_id) {
            await conn.query('DELETE FROM group_join WHERE activity_id = ? AND order_id = ?',
                [order.activity_id, orderId]);
            await conn.query('UPDATE group_activity SET current_people = GREATEST(current_people - 1, 0) WHERE id = ?',
                [order.activity_id]);
        }
        await conn.query('UPDATE `order` SET status = ?, cancel_time = NOW() WHERE id = ?',
            [ORDER_STATUS.CANCELLED, orderId]);
        await conn.commit();
        return { order_id: parseInt(orderId), status: ORDER_STATUS.CANCELLED };
    } catch (err) {
        await conn.rollback();
        throw err;
    } finally {
        conn.release();
    }
}
```

```javascript
const multer = require('multer');
const path = require('path');
const fs = require('fs');
const { success, fail, serverError } = require('../utils/response');

const UPLOAD_DIR = path.join(__dirname, '../public/uploads');
if (!fs.existsSync(UPLOAD_DIR)) fs.mkdirSync(UPLOAD_DIR, { recursive: true });

const storage = multer.diskStorage({
    destination: (req, file, cb) => cb(null, UPLOAD_DIR),
    filename: (req, file, cb) => {
        const ext = path.extname(file.originalname) || '';
        const safeName = `img_${Date.now()}_${Math.floor(Math.random() * 10000)}${ext}`;
        cb(null, safeName);
    }
});

function fileFilter(req, file, cb) {
    const allowed = /^image\/(jpeg|jpg|png|gif|webp)$/;
    if (allowed.test(file.mimetype)) cb(null, true);
    else cb(new Error('仅支持上传 jpg/png/gif/webp 图片文件'), false);
}

const upload = multer({ storage, fileFilter, limits: { fileSize: 5 * 1024 * 1024 } });

async function uploadImage(req, res) {
    try {
        if (!req.file) return fail(res, '未检测到上传文件');
        const url = `/public/uploads/${req.file.filename}`;   // 静态资源可访问 URL
        return success(res, { url, filename: req.file.filename, size: req.file.size }, '上传成功');
    } catch (err) {
        return serverError(res, err.message);
    }
}

async function uploadImages(req, res) {
    try {
        if (!req.files || req.files.length === 0) return fail(res, '未检测到上传文件');
        const list = req.files.map(f => ({
            url: `/public/uploads/${f.filename}`, filename: f.filename, size: f.size }));
        return success(res, list, '上传成功');
    } catch (err) {
        return serverError(res, err.message);
    }
}

module.exports = { upload, uploadImage, uploadImages };
```

## 附录 C：数据统计 SQL 与接口源码

### C.1 核心统计 SQL

```sql
-- 销量统计（有效订单，按日）
SELECT DATE(o.create_time) AS day,
       SUM(oi.quantity) AS quantity,
       SUM(oi.quantity * oi.price) AS sales
FROM `order` o JOIN order_item oi ON oi.order_id = o.id
WHERE o.status IN (1,2,3,4)
GROUP BY DATE(o.create_time) ORDER BY day;

-- 营收统计（按日）
SELECT DATE(create_time) AS day, SUM(total_amount) AS revenue, COUNT(*) AS order_count
FROM `order` WHERE status IN (1,2,3,4)
GROUP BY DATE(create_time) ORDER BY day;

-- 订单状态分布
SELECT status, COUNT(*) AS count FROM `order` GROUP BY status;

-- 热门商品 TOP N
SELECT oi.product_id, oi.product_name,
       SUM(oi.quantity) AS sold_count,
       SUM(oi.quantity * oi.price) AS sales_amount
FROM order_item oi JOIN `order` o ON oi.order_id = o.id
WHERE o.status IN (1,2,3,4)
GROUP BY oi.product_id, oi.product_name
ORDER BY sold_count DESC, sales_amount DESC
LIMIT 10;
```

async function hotProducts(params) {
    const { limit = 10, start, end } = params;
    const dateCond = buildDateCondition('o.create_time', start, end);
    const [rows] = await pool.query(
        `SELECT oi.product_id, oi.product_name, oi.product_image,
                SUM(oi.quantity) as sold_count,
                SUM(oi.quantity * oi.price) as sales_amount
         FROM order_item oi JOIN \`order\` o ON oi.order_id = o.id
         WHERE o.status IN (1,2,3,4) ${dateCond.sql}
         GROUP BY oi.product_id, oi.product_name, oi.product_image
         ORDER BY sold_count DESC, sales_amount DESC LIMIT ?`,
        [...dateCond.values, parseInt(limit)]);
    return rows.map((r, idx) => ({
        rank: idx + 1, product_id: r.product_id, product_name: r.product_name,
        product_image: r.product_image,
        sold_count: Number(r.sold_count || 0),
        sales_amount: Number((r.sales_amount || 0).toFixed(2))
    }));
}

## 附录 D：订单状态流转白名单（后端强制管控）

```javascript
const STATUS_FLOW = {
    0: [1, 2, 5],  // 待付款 -> 支付(团购1/普通2) 或 取消
    1: [2, 5],     // 待成团 -> 成团发货 或 取消
    2: [3, 5],     // 待配送 -> 配送中 或 取消
    3: [4],        // 配送中 -> 已完成
    4: [],         // 已完成（终态）
    5: []          // 已取消（终态）
};
function canTransition(from, to) {
    return (STATUS_FLOW[from] || []).includes(to);
}
```

> 说明：任何状态变更（支付、取消、管理员强制改单）都必须先经 `canTransition` 校验，非法流转直接拒绝，从而在上海量并发与多端操作下保证订单状态机不被破坏。
